React Vite Node.js Express MongoDB Mongoose

Características de este desarrollo Full Stack

Una sola tecnología en todo

React (frontend) y Node.js/Express (backend) usan JavaScript: un solo lenguaje en todo el proyecto.

API REST + JSON

El frontend pide datos al backend con GET, POST, PATCH y recibe respuestas en JSON.

Base de datos flexible

MongoDB (NoSQL) guarda reportes, usuarios y votos con esquemas que pueden evolucionar.

Escalabilidad

Capas separadas (rutas, controladores, modelos) que crecen sin rehacer el código.

Seguridad

Contraseñas con hash (bcrypt) y autenticación con tokens JWT.

Funciona 100% en local

Sin costos: MongoDB en tu PC, backend en localhost:5000 y frontend en localhost:5173.

React + Vite

Node.js + Express

Servidor que recibe las peticiones HTTP y responde JSON.

API REST

Base de Datos - MongoDB (lo que se guarda)

Colección User

nombre, email, passwordHash, rol (ciudadano/admin).

Colección Report

título, descripción, lat/lng, gravedad, foto, estado, votos.

Mongoose (ODM)

Define los modelos y valida los datos desde Node.js.

Los reportes se guardan con coordenadas (lat/lng) para dibujarlos en el mapa del frontend.

  • Frontend hace peticiones a http://localhost:5000/api con Axios y el token JWT.
  • Express valida el token, consulta MongoDB con Mongoose y devuelve JSON.
  • React dibuja esos datos en el mapa y en las listas de la interfaz.
  • CORS autoriza que el frontend (5173) hable con el backend (5000).

Tipo de desarrollo elegido: SPA con CSR

SPA + CSR - La elegimos

React renderiza todo en el navegador y pide datos al API. Perfecta porque nuestra app exige login y el SEO no es clave.

ReactSPA

SSR / SSG (futuro)

Si algún día la app debe venderse bien en buscadores, migraríamos a Next.js sin cambiar MongoDB ni la API.

PWA

En una versión futura, instalar la app en el celular y avisar notificaciones.

Decisión según criterio: la app es privada y dinámica, así que el renderizado en el cliente (CSR) es el correcto.
